## F1 — P2 Resolve typed script arguments before lowering function parameter defaults
- Location: `crates/otter-lang/src/lower.rs:1678` (`read_name`); declaration ordering at line 335 and `fn_params` at line 893.
- Evidence: function headers lower before the pass calling `const_decl`, so `typed_defines` is still empty when `fn_params` calls `literal_now`/`read_name`. With host defines `{n: "50"}`, the following program successfully returns **String("50")**, while an ordinary `@n` in a body is Int(50):
  ```shards
  @const(n 10 ignore-redefined: true)
  @fn(F input: None output: String params: {x: @n} { x })
  F
  ```
  Changing the function's output to `Int` exposes a compose type mismatch instead of producing 50. This happens even with the default declaration textually before the function. Without a host override, the same header cannot resolve `@n` at all because constants have not been registered; that general ordering limitation predates this range, but the raw-string bypass defeats the new typed-argument guarantee when an override exists.
- Impact: one script argument has different types depending on where it is read, and valid typed function defaults fail to compose. Ordinary reads, including reads through another constant or `#( )`, do not repair a value already captured in a function signature.
- Suggested direction: register and parse script-argument defaults before any path that can consume defines, or defer lowering function defaults until the argument bindings are ready. Cover both supplied and omitted arguments in function headers, including included declarations.

## F2 — P2 Keep the Session sink active during preserving reload and destruction
- Location: `crates/otter-lang/src/session.rs:104` (new sink contract), `reload_preserving` at line 395 (`install_revision`), and Session's implicit field destruction.
- Evidence: a host async shard whose pending future emits `"cleanup"` in `Drop` was started with `Session::tick` under a stream sink. `stop()` and full `reload()` route the cleanup line to the stream exactly once. Replacing the root using `reload_preserving()` routes it to an outer `log::capture` instead, leaving the session stream empty. `drop(session)` does the same. `Mesh::install_revision` calls `finish` for replaced instances directly, and Session has no Drop implementation to scope its mesh destruction to the configured sink. Reproduction recipe and shard below.
- Impact: a host loses cleanup/error/progress lines from its configured stream during normal hot reload or implicit shutdown; they can go to stdout or another host capture. The behavior depends on which equivalent cancellation API the host uses.
- Suggested direction: scope all execution cleanup paths to the configured sink, including preserving replacement and session destruction, preserving the existing `None` inheritance rule. Keep full-reload/explicit-stop positive controls in tests.

## F3 — P2 Drop a replaced stream outside the thread-local mutable borrow
- Location: `crates/otter-core/src/log.rs:107`, `with_sink::Restore::drop`, newly exposed by `Sink::stream` at line 47.
- Evidence: `*c.borrow_mut() = outer` destroys the installed sink while holding the mutable RefCell borrow. A stream can own arbitrary host resources; if the last callback Arc is released there and a captured resource's destructor logs, `emit_line` panics at line 89 with `RefCell already mutably borrowed`. This minimal safe-Rust reproduction panics on normal exit:
  ```rust
  use otter_core::log::{emit, with_sink, Sink};
  struct Guard;
  impl Drop for Guard {
    fn drop(&mut self) { emit("sink dropped".into()); }
  }
  let guard = Guard;
  with_sink(Some(Sink::stream(move |_| { let _ = &guard; })), || {});
  ```
  Observed under `catch_unwind` in the scratch test. If restoration occurs while another panic is unwinding, this destructor-induced second panic can abort; that abort case was inferred from the code, not executed.
- Impact: the advertised restoration/reentrancy guarantee fails for a legitimate stream-owned resource that logs its release. The old buffer held only strings, so it could not execute such host destructors.
- Suggested direction: replace the TLS value, move the displaced sink out, end the borrow, then drop it. Test resource destruction during normal exit and unwinding. Ordinary callback logging/nested captures and a callback panic already work; this is specifically destruction during restoration.

## F4 — P2 Check duplicate constant declarations before accepting an override
- Location: `crates/otter-lang/src/lower.rs:1899`–1909, insertion/return before the duplicate check at line 1910.
- Evidence: with defines `{n: "50"}`, this program loads and returns **String("50")**:
  ```shards
  @const(n 10 ignore-redefined: true)
  @const(n "ten" ignore-redefined: true)
  @n
  ```
  Without the host define, the identical declarations report `duplicate-binding`. Reversing their order with the host define changes the resulting type to Int. Every supplied-default declaration overwrites the prior `consts` entry without checking it.
- Impact: adding a command-line override silently suppresses a program-level duplicate error and makes declaration/include ordering determine the argument's type. The documented exception is a script argument replacing its default, not a second constant silently changing the first default's contract.
- Suggested direction: distinguish a collision with a host argument from a duplicate source declaration before insertion. Pin the intended duplicate-default policy with and without defines, and across included files.

## F5 — P3 Reject `none` as an unsupported default even without an override
- Location: `crates/otter-lang/src/lower.rs:1860` and line 1879.
- Evidence: `@const(n none ignore-redefined: true) @n` loads successfully with no defines. The new validation only requires `BlockKind::Literal`, which includes `Literal::None`; it rejects None only when an override is supplied and parsing reaches the `Literal::None => None` arm. No argument string can override this accepted default.
- Impact: contradicts the metaprogramming contract that a default must be a number, string or bool literal, and accepts a declaration whose advertised override is unusable. Diagnostics depend on whether the host supplied a value rather than identifying the invalid declaration consistently.
- Suggested direction: validate the supported literal kinds before checking whether an override exists, and report `declaration` at the unsupported default.

## F6 — P3 Correct the claimed Session instance-to-wire mapping
- Location: `docs/embedding.md:93`, “Session and the mesh map instances to wires”.
- Evidence: `Mesh::instance_wire` exists only while its record is retained, but Session exposes neither that method nor its mesh. `Session::Finished` contains `wire` and `outcome`, without the instance ID, and `tick` retires finished records before returning. A host using the documented Session stream cannot use the claimed public mapping, even by queueing lines and examining them after the tick.
- Impact: the embedding guide promises an attribution capability that the recommended public API cannot supply, particularly for spawned wires or several instances. The delivered numeric instance ID alone does not establish which wire produced a line.
- Suggested direction: accurately document the current limitation or expose durable attribution suitable for streamed lines. Account for retirement and fresh-mesh ID reuse if an API is added; simply forwarding a transient mesh lookup after tick is insufficient.

## Additional assessment

- `emit_line` correctly clones the sink out of TLS before calling host code. A bounded callback that emits a second line, then nests `capture`, works without borrow errors or duplication. A callback panic unwinds through `with_sink` and the outer capture receives later lines. An unconditional callback that calls the same logger would recurse by its own definition; no separate defect is claimed for that.
- `Log` includes `ctx.instance()` and preserves its pass-through output and prefix formatting. Buffers intentionally retain only text. The submitted Session test checks prompt delivery and an instance being present; it does not exercise cancellation or attribution lookup.
- Existing `otter_io::runtime::spawn` installs the captured sink for each poll, and `spawn_blocking` scopes the whole closure. The stream probe received exactly one async-before, async-after (after `yield_now`) and blocking line. Workers keep the sink captured when spawned, including after the host's dynamic scope returns. This test does not claim coverage of arbitrary Tokio tasks started outside those wrappers or logs from future destructors outside their poll scope.
- Typed values worked in pipeline and native parameter reads, constants referencing the default, `#( )`, evaluated aliases, and f-strings. An included file declaring the default and an evaluated alias returned 51 with `n=50`. Invalid `n=many` produced `script-argument-type` at `lib.shs:1:8`, the declaration name, as promised. The implementation shares these paths through `read_name`; F1 is the early consumer bypass.
- H5 is implementable as a future change: shared per-spawn completion state can outlive scheduler records and support multiple waiters, while a separate ownership tree controls cancellation and prunes finished children. Publishing completion after cleanup is compatible with H6's distinction between cleanup and external-worker quiescence. The accepted unprefixed names supersede the proposal's earlier `Wire.Wait`/`Wire.Stop`; existing docs describing today's pass-through Spawn/detached children describe the current implementation, not an already implemented A2. Local 1.x `wires.cpp` confirms the chosen Wait/Peek/Spawn names, Wire parameter, Spawn's wire output and default-false Joint. No blocking contradiction found in the decision.
- H5 implementation details still need to be pinned by its tests: timeout wakeups under OnNotify must occur without relying on another tick polling a parked future; Peek's stopped/cancelled behavior should be explicit; dropped waiter registrations must be removed; cancellation must include queued children and complete handles on mesh destruction. These are follow-through requirements/design clarifications, not claims that unimplemented A2 code is defective. No external claims of Astra review or CI success were independently verified.

```rust
use otter_core::{Args, ComposeCtx, Composed, Result, ShardType, Type, Var};
use otter_core::describe::ShardDesc;
use otter_core::instance::LeafCtx;
use otter_core::shards::async_shard::{AsyncShard, async_type};
struct PendingLog;
impl std::future::Future for PendingLog {
  type Output = Result<Var>;
  fn poll(self: std::pin::Pin<&mut Self>, _: &mut std::task::Context<'_>)
    -> std::task::Poll<Self::Output> { std::task::Poll::Pending }
}
impl Drop for PendingLog {
  fn drop(&mut self) { otter_core::log::emit("cleanup".into()); }
}
struct Park;
impl AsyncShard for Park {
  type Compiled = ();
  type Op = PendingLog;
  const DESC: ShardDesc = ShardDesc::undocumented("Test.Park", 1);
  fn compose(_: &Args, _: &mut ComposeCtx<'_>) -> Result<Composed<()>> {
    Ok(Composed { compiled: (), output: Type::none() })
  }
  fn start(_: &(), _: &mut impl LeafCtx, _: &Var) -> Result<PendingLog> {
    Ok(PendingLog)
  }
}
static PARK: ShardType = async_type::<Park>();
```

For each case create a new Session and an `Arc<Mutex<Vec<String>>>` collecting its stream's `line.text`. Reload source `Test.Park`, tick once to park it, then run the selected operation inside an outer `log::capture`: (a) `stop()`, (b) `reload` with source `none`, (c) `reload_preserving` with source `none`, (d) `drop(session)`. Use empty defines throughout. Observed: (a)/(b) stream `["cleanup"]`, outer `[]`; (c)/(d) stream `[]`, outer `["cleanup"]`. Expected for all four: the former, with exactly one cleanup line.
