## F1 — P1 `take_op` and `take_slot_op` alias a shared and a mutable reference to `scratch` (undefined behavior, a regression)
- Location: `crates/otter-core/src/inline.rs:836` (`take_op(&*value, key, &mut scratch)`), `:849` (`take_slot_op(&*value, *index, &mut scratch)`); callees at `:1082` and `:1092`.
- Evidence: the accumulator `value` is `&scratch` on entry and after every Take, TakeSlot, Push and generic operation, so an out-of-line Take or TakeSlot on the flow input or on a previous result passes `&*value` and `&mut scratch` naming the same `Var` into a call where both are protected. Miri (Stacked Borrows): "trying to retag from <..> for SharedReadOnly permission ... tag does not exist in the borrow stack", tag created at `inline.rs:836:42`, invalidated by the Unique retag at `836:56`, failing at `take_op`'s entry (`1082:12`); the same at `849:47/849:64` for `take_slot_op`. Tree Borrows: "write access through <..> is forbidden" at `assign(scratch, new)` (`inline.rs:1087` → `var.rs:1307`). The base computed `new` from `&*value` inside `run`, ending that borrow before `assign(&mut scratch, new)`, as `run`'s SAFETY comment states ("Reads end before any write"). `key` never aliases `scratch` (a constant or a frame slot). The inline sequence-index and struct-slot paths are sound (`copy` ends the borrow first). Repro (temporary tests in `inline::tests`):
```rust

  #[test]
  fn review_take_by_key_on_scratch() {
    let inner: Table = [("b", Var::Int(5))].into_iter().collect();
    let outer: Table = [("a", Var::from_table(inner))].into_iter().collect();
    // value == &scratch on entry (the input); then again after the first Take.
    let code = instructions([
      Op::Take(Operand::Const(Var::string("a"))),
      Op::Take(Operand::Const(Var::string("b"))),
    ]);
    let (_, out) = run(&code, 0, Var::from_table(outer), &mut [], &mut [], &NoCalls).unwrap();
    assert_eq!(out, Var::Int(5));
  }

  #[test]
  fn review_take_slot_error_on_scratch() {
    let code = instructions([Op::TakeSlot(0)]);
    assert!(run(&code, 0, Var::Int(1), &mut [], &mut [], &NoCalls).is_err());
  }

  #[test]
  fn review_take_out_of_range_on_scratch() {
    use std::sync::Arc;
    let code = instructions([Op::Take(Operand::Const(Var::Int(-1)))]);
    let r = run(&code, 0, Var::from_seq(Arc::new(vec![Var::Int(1)])), &mut [], &mut [], &NoCalls);
    assert!(r.is_err());
  }
```
- Impact: language-level UB on a hot path in `#[inline(never)]` functions whose reference arguments LLVM may treat as `noalias`/`readonly`. The callees read the value into an owned `new` before `assign` drops the old scratch, so no freed memory is read and native tests pass; whether current code generation miscompiles is unverified. Any Miri run over these paths fails.
- Suggested direction: never pass a `&` and a `&mut` that can alias. Either return the new value (`Result<Var, Box<Error>>`) and keep `assign(&mut scratch, new)` in `run` (re-measure: the commit chose the scratch write to return one register), or pass raw pointers derived from one `&raw mut scratch` and dereference only after the read ends (check under both Stacked and Tree Borrows). Make the three repro tests permanent so the existing Miri command covers them.
