## Remaining code and design assessment

No additional correctness finding within this scope. `assign_copy_slow` preserves the original clone-before-drop body, including String, Seq, Table and Bytes reference ownership. Both Set arms still exclude identical source/destination slots before making references. Frame bindings and constants cannot name the stack scratch slot. Valid sequence-index and table-slot fast paths make an owned copy before replacing scratch, preserving nested heap values; map tables also support the slot accessor. Table key misses still yield None; vector indexing and invalid input/key cases still select the original generic implementation. Error boxing/unboxing preserves the error, and metering still records and charges the current instruction before lookup. These semantic observations do not excuse F1's invalid references, even on paths that return errors without writing scratch.

Keeping storage-kind dispatch behind explicit non-inlined helpers is a sound performance discipline, assuming stable Var size, alignment and plain-tag classification. It is not a proof that adding any future variant cannot change generated machine code: compiler optimization, enum layout and indirect dependencies still require the gates. The source comment's blanket statement that all errors are calls is also stronger than the code: Inc, Push and LoopTest still construct some errors in run. Those existing fixed-operation paths do not themselves demonstrate renewed dispatch by heap value kind. A documentation follow-up should also reconcile `docs/values-and-types.md` §2, which still says Set counts references inline, with this commit's new rule. I treat these as documentation qualifications, not additional blockers.
