## F1 — P2 Reject object-containing function defaults before compiling them
- Location: `crates/otter-core/src/compose.rs:1771`, `ComposeCtx::compose_call`; `crates/otter-core/src/function.rs:110`, `FunctionDef::param_default`.
- Evidence: the new `holds_object` check covers explicitly supplied function arguments only. An omitted parameter takes `Operand::Const(default.clone().into_struct_tables())` without the check. A public host definition `FunctionDef::new("F", Type::none(), object.type_of()).param_default("p", object).body(vec![get("p")])`, called with no arguments, compiles and returns the same object. Reproduced for both a direct object and a table containing a sequence containing the object. Code below.
- Impact: violates H1's never-a-constant guarantee using the normal function API and shipped Get shard, with no custom compose implementation. The resource becomes part of shared compiled call operands and function-definition dependencies/cache retention instead of runtime-only state; struct-table conversion does not remove it.
- Suggested direction: validate defaults as well as explicit arguments, recursively, with `object-in-constant` diagnostics. Validate the function definition before retaining it in compiled/cache dependencies, including defaults overridden by a caller. Add regression tests for direct and nested defaults, and compose-time use of such functions.

## F2 — P2 Apply object constant validation to undeclared shard parameters
- Location: `crates/otter-core/src/args.rs:249`, early return at lines 261–263; new validation at line 384 is never reached.
- Evidence: `Params::Undeclared` clones all positional values directly into `Args`. This remains a supported public path (`ShardDesc::undocumented` and `Args::positional`). A leaf that stores its first positional constant in `Compiled` accepts an object and returns it at activation; the identical argument to a declared Const is rejected. Full reproduction below.
- Impact: existing host shards using the compatibility parameter path bypass the new engine-level guarantee. The check should not depend on whether a shard has migrated its metadata. This is distinct from a malicious host directly constructing arbitrary compiled data.
- Suggested direction: reject object-containing literal arguments before the declared/undeclared split, retaining useful positional diagnostics, and cover the compatibility path with a test.

## F4 — P3 Validate the complete object type name against the language grammar
- Location: `crates/otter-core/src/catalog.rs:66`–70, `Catalog::with_objects`.
- Evidence: only each dot-separated component's first character is checked. `ObjectType::new("Test.Bad Name")` is accepted by `Catalog::new(&[otter_core::shards::CATALOG]).unwrap().with_objects(&[&[&BAD]])`, but a function signature `@fn(F input: Test.Bad Name output: None params: {} { none }) none` fails to load. Spaces and other delimiters cannot form the advertised single type name. Reproduced in the archive.
- Impact: a catalog reports successful registration of types scripts cannot name; errors emerge later at use sites rather than at the invalid registration.
- Suggested direction: validate the entire qualified name using the lexer-compatible identifier grammar, and test whitespace/punctuation as well as unqualified and lowercase names.

## Reproductions for F1 and F2

Append the following to the reviewed `crates/otter-core/tests/values.rs` in a disposable snapshot. It uses that file's existing `Session`, `run`, imports and shard-definition helpers. Run `cargo test -p otter-core --test values review_`. Both currently pass, demonstrating acceptance; a fix should instead assert the object-in-constant diagnostic.

```rust
#[test]
fn review_undeclared_object_constant() {
  use otter_core::{Args, ComposeCtx, Composed, Result, ShardType};
  use otter_core::describe::ShardDesc;
  use otter_core::instance::{InstanceCtx, LeafCtx};
  use otter_core::shard::{Flow, ParamValue};
  use otter_core::shards::leaf::{LeafShard, leaf_type};
  struct LegacyConst;
  impl LeafShard for LegacyConst {
    type Compiled = Var;
    type State = ();
    const DESC: ShardDesc = ShardDesc::undocumented("Test.LegacyConst", 1);
    fn compose(args: &Args, _: &mut ComposeCtx<'_>) -> Result<Composed<Var>> {
      let ParamValue::Value(v) = &args.positional()[0] else { panic!() };
      Ok(Composed { compiled: v.clone(), output: v.type_of() })
    }
    fn instantiate(_: &Var, _: &mut InstanceCtx) -> Result<()> { Ok(()) }
    fn activate(v: &Var, _: &mut (), _: &mut impl LeafCtx, _: &Var) -> Result<Flow> {
      Ok(Flow::Next(v.clone()))
    }
  }
  static LEGACY: ShardType = leaf_type::<LegacyConst>();
  let value = Var::object(Session(Arc::default()));
  let out = run(&mut Mesh::new(), vec![ShardDef::new(&LEGACY, vec![val(value.clone())])]).unwrap();
  assert_eq!(out, value, "object was stored in Compiled and returned at runtime");
}


#[test]
fn review_function_default_object_constant() {
  use otter_core::function::FunctionDef;
  let object = Var::object(Session(Arc::default()));
  for value in [object.clone(), Var::table([("deep", Var::seq(vec![object.clone()]))])] {
    let mut mesh = Mesh::new();
    mesh.add_function(FunctionDef::new("F", Type::none(), value.type_of())
      .param_default("p", value.clone()).body(vec![get("p")]));
    let out = run(&mut mesh, vec![call("F", vec![])]).unwrap();
    assert_eq!(out, value, "default object reached a compiled constant");
  }
}
```

## Other assessment

- Storage: Object follows the existing non-plain tag classification, with matching clone/drop arms in both normal and assignment helpers. The thin Arc refcount operations use the correct `ObjectBox` pointer; no new reference/accumulator alias was found. Identity equality and hashing agree, including within collections. Downcasting uses safe `Any` trait upcasting, not the script type name. The mutex and relaxed atomic counter each serialize unique increments in their target configuration; 64-bit exhaustion is theoretical rather than a practical finding. The no-64-bit branch was inspected, not executed here.
- Constants/evaluation: declared shard arguments and explicitly supplied function values are checked before table conversion. `holds_object` visits sequence/table descendants and memoizes shared storage. Shard metadata defaults use the limited scalar `DefaultValue` enum and cannot hold objects. Compose-time final results are checked before insertion into the evaluation cache; this does not repair F1's admission of defaults into compiled code/dependencies. Host shards remain ineligible for compose-time evaluation by identity. Arbitrary host `Compiled` types are a trusted contract, so this review does not claim the type system can prohibit a host deliberately storing a resource itself.
- Types: equality by interned name, structural ordering, union membership and Any acceptance are consistent; downcasting still checks the Rust type. Catalog duplicate checks also apply across chained registrations. F4 is the name-validation gap.
- Services: `Option<Arc<HashMap<...>>>` leaves default services allocation-free, and preserving candidates share the map. Mutations copy the map while keeping service Arcs shared. Activation reads the existing revisions reference; evaluation constructs empty revisions. `Session::set_services` updates both active and future meshes between ticks; operations retaining an old Arc remain valid. Supplementary replacement/reload tests passed. Module fallback services and worker leases remain author obligations under H6, not automatic quiescence.
- Guards: `dispatch_custom` resets state on completion, returned error, invalid child entry and propagating signals. Child-frame errors travel back through the same completion path; cancellation drops custom state during tree cleanup. Nested suspended Stop/error and cancellation tests passed in addition to the submitted tests. No guard-reset defect found in this scope. The submitted error case is a leaf VM failure; keeping permanent nested/suspended coverage and adding Restart would strengthen the contract tests. Panicking/blocking destructors and real module worker cancellation were not certified.
- Performance: no changes to `inline.rs` or `stackless/engine.rs`, unchanged value size/plain-tag boundary, and services behind the existing revisions pointer support the reported lack of ordinary activation cost. Locally, instructions match exactly for 81/85 shared workloads; two differ by 0.01 instruction/iteration (`take-table/256` -0.01, `do-int/8` +0.01), `push-shared-seq/256` is 26827 → 26668, and reload is 357211.40 → 357086.60 (-124.80, approximately -0.035%). Allocations and bytes match on all 85. These are this environment's observations, not a reproduction of CI's exact reload delta or byte-identical assembly; the small differences and allocation-heavy workload were not further attributed. The source is consistent with a small compose/reload cost change and no general VM regression. F3 still prevents a green committed gate.
