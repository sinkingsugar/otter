## F1 — P2 Charge the string traversal when padding returns its input unchanged

- Location: `crates/otter-core/src/shards/text.rs:1493–1507`, `Pad::activate`.
- Evidence: `text.chars().count()` scans the input (line 1494), but a string already at its width returns at line 1500, before `meter_bytes(input, meter)`. With a 1,048,576-character literal `s`, `#( s = ... Repeat({s | String.PadStart(width: 0)} times: 200) 1 )` passes `otter check` (also with `PadEnd`); the same with `Count`, which does the same traversal, fails with `the evaluation ran out of fuel (limit 10000000) [expansion-budget]`.
- Impact: both new compose-time-eligible shards bypass the work budget on their common no-padding path.
- Suggested direction: charge the traversal before counting and before any return after it, or avoid the traversal where possible (non-positive widths) and charge every path that scans. Add a compose-time budget regression for both directions.

## F2 — P2 Reject positive widths that cannot fit `usize` instead of treating them as no padding

- Location: `crates/otter-core/src/shards/text.rs:1495–1500`, `Pad::activate`.
- Evidence: the conversion of `width` to `usize`, the subtraction of the length and the zero check share one early return. On `wasm32-wasip1`, `"x" | String.PadStart(width: 4294967296)` and the same with `PadEnd` complete with `"x"`.
- Impact: a wrong result instead of an error on 32-bit targets (WASI, ESP32); an unrepresentable width evades the allocation-error path.
- Suggested direction: separate non-positive widths and widths at or below the length from an overflowing positive width, which fails at activation. Add a 32-bit regression for both shards.
