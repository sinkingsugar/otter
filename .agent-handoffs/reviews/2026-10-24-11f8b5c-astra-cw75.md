## F1 — P1 Erase required keys when filtering mixed open tables

- Location: `crates/otter-core/src/shards/iterate.rs:396–406`, especially the `t.rest.is_none()` guard at line 398.
- Evidence: `filtered()` removes known keys only for **fixed** tables. A mixed open input such as `Type::table([("a", Type::int())], Some(Type::string()))` keeps its original type, including the guarantee that `a` exists and holds an Int. A core-API repro: compile a wire at that input type whose flow is `vec![iterate(&FILTER, vec![konst(Var::Bool(false))], &[]), take(val(Var::string("a")))]` and spawn it with `Var::table([("a", Var::Int(1)), ("b", Var::string("text"))])`. Filtering collects no indices and `rebuild(..., true)` produces an empty table, but `Filter` declares the original mixed-table output type, so `Take("a")` composes to Int (`data.rs:259`) while the run-time lookup returns None. Debug/output-check builds should reject the empty table at `Rebuild`; unchecked release execution can propagate None through a statically Int result. Not executed.
- Impact: compose-time type unsoundness for host-provided mixed table types, also inside an input union.
- Suggested direction: turn every table member into a table with no required keys and a rest type equal to the union of its known-field types and existing rest type. Add a regression with a mixed open table asserting the filtered result is admitted by its declared type and that a removed key's inferred type includes None.

## F2 — P2 Validate sequence-pattern length independently of named bindings

- Location: `crates/otter-lang/src/lower.rs:1396–1414`, especially the underscore-eliding `filter_map` at line 1406.
- Evidence: sequence destructuring emits a `Take` only for a named position, with no check that the input has every position of the pattern. `[1] = [a _]` binds `a` to 1 instead of failing; `[1] = [a _ _]` likewise. §3 requires shorter sequences to fail; §7 changes only the wording. The short-sequence test uses `[a b c]`, so every position is read and this case is missed. The lowering also omits a sequence-kind check: `[1 2] | ToFloat2 = [a b]` is accepted through vector-capable `Take`s, contrary to §3 and not recorded as a deviation.
  - Observed by the publishing session with the `otter` CLI at this commit: `[1] = [a _]` then `a | Log` prints `1`; `[1 2] | ToFloat2 = [a b]` then `a | Log` prints `1` (root `1.0`).
- Impact: destructuring silently accepts malformed positional input when trailing fields are skipped, and accepts a broader input kind than documented.
- Suggested direction: validate sequence kind and minimum pattern length once, independently of which positions bind names, keeping passthrough. Tests for trailing underscores, multiple trailing underscores, dynamic short input and vector input.
